# PawPal JSON 持久化替代设计

## 背景

当前受控开发环境持续拒绝 npm registry，无法下载 Prisma 和 PostgreSQL 相关依赖。为不中断项目开发，PawPal 的本地演示版改用 Node 标准库实现的 JSON 文件持久化；页面与业务层不直接依赖具体存储实现。

## 设计

新增 `src/lib/store/`：

- `types.ts`：账户、家庭、宠物、任务、成长记录、健康记录与会话的领域数据类型。
- `json-store.ts`：在 `data/pawpal.json` 读写快照；写入经临时文件和原子重命名完成，避免中途写坏文件。
- `repository.ts`：提供账户、家庭、宠物、任务和记录的查询/修改接口；页面和 API 只调用该接口。
- `seed.ts`：首次启动建立一个温暖的演示家庭、两只宠物和今日照护任务，便于直接展示。

认证在演示版使用本地账户与随机 HttpOnly 会话 Cookie。密码使用 Node 的 `scrypt` 和随机 salt 哈希，不保存明文。邀请链接仍只保存摘要，并可通过单进程互斥队列保证“一个邀请只能接受一次”。

## 已知边界

- JSON 存储适用于单一 Node 进程和课程演示；不支持多个 Web 实例之间的分布式事务或锁。
- Docker Compose 中不再要求 PostgreSQL 服务；数据目录作为容器卷挂载，重启不丢失数据。
- `repository.ts` 是替换点。网络恢复后可用 PostgreSQL/Prisma 实现同一接口，不改 UI、路由或业务规则。

## 验证

- 单元测试覆盖账号唯一性、密码不明文、成员唯一性、邀请一次性接受、任务单次完成、权限范围与 JSON 原子写入。
- 端到端演示覆盖注册/登录、创建家庭、添加宠物、完成今日任务、记录成长瞬间。
- README 清楚声明 JSON 演示模式的单进程限制。
